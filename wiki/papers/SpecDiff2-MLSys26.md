# SpecDiff-2：用扩散草稿模型加速自回归推理

> **原题**：SpecDiff-2: Scaling Diffusion Drafter Alignment for Faster Speculative Decoding

> **一句话总结**：通过并行扩散草稿、面向连续接受长度的蒸馏，以及验证模型对多份草稿的选择，减少大模型逐 token 解码的串行等待。[^paper]

**阅读状态**：已阅读会议正式版 MinerU 全文、附录与关键图表；表 2 和表 7 的数据集列名与表注、附录数据描述不一致，具体评测集待核对。会议页面未列独立补充材料，因此暂列待复核。[^paper]

## 问题与动机

推测解码先由草稿模型提出多个 token，再由目标模型并行验证；草稿生成耗时过长或前几个 token 经常被拒绝，都会抵消减少目标模型调用次数的收益。自回归草稿本身仍需要逐 token 运行。论文采用扩散语言模型一次并行预测多个位置，并针对扩散草稿在不同位置的接受率不一致进行对齐（§1–4）。[^paper]

这里加速的仍是**自回归目标模型的生成**：扩散模型负责提出候选，最终输出由目标模型验证。它不同于直接部署扩散语言模型替代目标模型，也不意味着任何场景都能降低推理成本。

## 关键观察 / 隐含假设

- **连续接受比单位置准确率更直接**：第 $j$ 个草稿 token 只有在前面的草稿都被接受后才能贡献这一轮的连续前缀。论文用各位置接受概率的前缀乘积之和描述期望接受长度（公式 3）。[^paper]
- **并行草稿依赖模型与硬件条件**：一个扩散步骤可同时给窗口内各位置产生预测，但草稿窗口、候选数和验证树增长后仍需更多计算与显存。[^paper]
- **加速取决于时间而非接受长度单一指标**：即使候选更容易被接受，草稿生成和多分支验证过慢也可能得不偿失。
- **无损是分布层面的结论**：随机采样时，维持目标模型的条件输出分布并不等于相同随机种子下逐 token 必然相同。该结论还依赖正确的条件概率、拒绝后的补偿采样和缓存实现。

## 核心方法

### 1. 扩散草稿与连续前缀蒸馏

给定已有前缀和长度为 $\gamma$ 的掩码窗口，扩散草稿模型并行预测各位置；实验采用一次去噪，DiffuCoder 的窗口为 32，DiffuLLaMA 为 16。直接提高平均位置正确率不足以体现前缀中较早位置的价值：第一个错误会截断本轮可接受的连续片段。Streak-distillation 因此借助目标模型概率，优化面向整段连续接受长度的对齐目标，而非只对单一位置做局部匹配（§5.1、附录 A）。[^paper]

训练草稿是为推理加速服务的准备步骤；其训练开销和模型存储不能忽略。图 2 显示，所测条件下该方法在窗口后部的接受率高于自回归式蒸馏，但这张图本身不是端到端加速实验。[^paper]

### 2. 自选择与验证

从一次草稿模型给出的各位置分布中采样 $K$ 份候选，目标模型计算每份候选各位置的条件概率；系统据此估计连续接受长度并选出一份，再用目标模型验证。附录 B.8 描述了共享前缀的树形打包和注意力掩码，目的是减少多候选的重复验证工作（§5.2、算法 1）。[^paper]

对选中候选的当前位置 $x$，论文以目标模型概率 $p(x)$ 接受它；否则从排除 $x$ 后重新归一化的 $p$ 中采样替代 token，然后结束该轮。对固定候选和条件分布，这两条路径输出任一 token 的总概率仍为目标分布；这一机制与常见的 $\min(1,p(x)/q(x))$ 接受规则不同。实际多分支实现仍须确保目标概率和缓存确实对应选中路径。[^paper]

## 批判性分析

### 论证链条

论文的论证链是：扩散模型降低串行草稿次数；连续前缀目标改善候选与目标模型的对齐；多候选选择进一步提高预期接受长度；最终通过墙钟吞吐实验检验收益。表 3 支持组合方案优于未对齐草稿，附录则显示目标模型规模和草稿代价会改变结论。[^paper]

### 假设压力测试

设计代价是额外的 7B 草稿模型、蒸馏成本、树形验证以及更高显存。论文对批处理主要讨论概念和资源随 batch 的增长，不能据此推断高并发服务的吞吐、排队延迟或成本收益。固定时间预算中的准确率变化来自更快生成带来的更多可用推理时间，不应与采样分布无损保证混为一谈。

### 实验可信度

结果包含真实 GPU 的墙钟计时，但实验集名称、显存表硬件与吞吐比的叙述口径存在冲突，限制了对具体数值的复现和外推。应结合原始配置与计时代码进一步核验。

## 局限与后续工作

- **待复核**：表 2/7 的数据集名称冲突、表 4 的 GPU 数量说明、附录 B.5 的速度比方向。论文附录 C.3 的不等式推导也存在方向与中间步骤问题；这里不把该证明视为独立确认。[^paper]
- 检查实际实现的树掩码、分支缓存和随机采样正确性，并评测高并发下的端到端吞吐与成本。

## 对 LLM 推理的启发

选择推测解码方案时，应同时测量草稿耗时、验证耗时、每轮连续接受 token、显存以及目标工作负载的真实端到端吞吐。离线条件下草稿可被充分训练，不代表多模型服务或高并发批处理中的资源预算仍然划算。与 [[SparseSpec-MLSys26]] 一样，这篇关注减少目标模型生成轮次，但采用扩散草稿和多候选选择，而非将两者等同。
