# DFlash：用块扩散生成推测解码草稿

> **原题**：DFlash: Block Diffusion for Flash Speculative Decoding

> **一句话总结**：DFlash 将目标模型多层隐藏状态注入轻量草稿模型的各层 KV，一次前向并行预测整个候选块，再由目标模型验证；实验显示其收益受模型、任务、并发和草稿成本影响。[^paper]

**阅读状态**：已读取 ICML 正式版 MinerU 全文，并对照原 PDF 核对架构图、草稿开销图、训练注意力图及本文引用的主要实验和消融表格。[^paper]

## 问题与关键观察

推测解码用草稿模型提前提出候选，目标模型批量验证，减少目标模型串行调用。若草稿模型仍逐 token 自回归生成，草稿长度增加会带来更多串行前向；若用大型扩散模型生成草稿，草稿自身的延迟和显存可能抵消收益。DFlash 的问题是：能否用小型扩散模型一次预测整个候选块，同时借助目标模型的上下文提高接受率（§1、§3）。[^paper]

每轮平均 token 延迟可近似写成 $(T_{draft}+T_{verify})/\tau$，其中 $\tau$ 是每轮平均推进的 token 数，包含目标模型额外生成的 token。提高接受长度只有在增加的草稿与验证成本足够小的时候才带来收益；比较方法时不能仅看接受率（§3.1）。[^paper]

## 方法

### 从目标模型获取上下文

目标模型先完成 prefill，输出首个 token。DFlash 从目标模型选定的多层提取隐藏状态，拼接并投影成上下文特征；这些特征分别投影成草稿模型各层的 Key 和 Value，写入草稿侧 KV cache。之后草稿模型各层都能访问目标模型上下文，而不是只在草稿输入层融合一次（§4.1、附录 A.3）。[^paper]

这里有两类不同状态：目标模型自身的 KV cache 服务目标模型验证；注入后的草稿侧 KV cache 为草稿模型提供上下文。特征提取、投影和草稿 KV 驻留都有成本，不能把小草稿模型的参数量直接当作全部额外开销。

### 并行草稿和验证

草稿块以目标模型生成的已知 token 为锚点，其余位置为掩码；块内位置可双向注意，一次前向同时预测候选。目标模型随后并行验证候选，连续接受的前缀才推进生成，拒绝后按具体解码算法修正，再进入下一轮（§4.1）。[^paper]

论文所谓无损依赖验证与采样过程的正确实现。贪心解码的目标是与相同目标模型的贪心结果一致；随机采样需保证目标模型条件分布，不能只凭“目标模型检查过”推导分布无损。浮点误差、批处理形状和实现差异仍可能导致实际结果不同。推测采样的分布证明见 [[Speculative-Decoding]]。

### 训练与部署匹配

训练时冻结目标模型，先从完整序列提取上下文特征，再从回答中随机选择锚点，掩码同块后续位置，训练草稿模型并行预测。不同训练块之间禁止互相注意，以免泄漏未来信息；块内位置则可互相注意。损失对较早位置赋予更高权重，因为一旦前面的候选被拒，后面的候选无法贡献连续接受前缀。草稿模型共享并冻结目标模型的词嵌入与输出头（§4.2）。[^paper]

## 实验与证据

实验主要使用 Qwen3 4B/8B、Qwen3-Coder-30B-A3B 和 LLaMA-3.1-8B，覆盖数学、代码与聊天；除另有说明外使用 H200。草稿通常为 5 层、块大小 16，Coder 使用 8 层，LLaMA 使用块大小 10；训练集约 80 万条，回答由目标模型生成以对齐目标行为（§5）。[^paper]

## 判断与局限

论文把草稿质量和草稿时间放在同一个成本模型里分析：目标模型多层特征提高候选质量，块内并行减少草稿的串行轮次。表 6 同时展示接受长度继续增长而加速回落，支持不能只按接受率选方案的判断。

实验主要在单 GPU 与公开基准上进行，SGLang 部分覆盖并发 1–32，不能直接外推到任意线上请求分布、尾延迟或多机部署。论文没有与其他扩散草稿方法作直接实验对照，原因是作者称缺少开源实现；因此不能把文中关于这些方法的讨论当作同条件实测排名（§5）。[^paper]

目标模型隐藏状态提取、草稿 KV cache、额外显存和训练成本会改变实际收益；长上下文实验主要报告接受长度。不同模型需要配套草稿训练和适配，若工作负载使验证阶段计算饱和，较长块可能得不偿失。可进一步测量真实请求轨迹下的 TTFT、TPOT、P99、额外显存与每输出 token 的总成本。
