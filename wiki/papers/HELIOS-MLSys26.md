# HELIOS：动态选择模型与提前退出层（MLSys 2026）

> **原题**：HELIOS: Adaptive Model and Early-Exit Selection for Efficient LLM Inference Serving

> **一句话总结**：HELIOS 根据请求流的提前退出分布选择候选模型，只加载预计常用的模型层，并按需要补充层或切换模型，以减少计算和显存占用。[^paper]

**阅读状态**：已阅读与会议正式 PDF 一致的 MinerU 全文，并核对方法、质量评测和主要实验表。[^paper]

## 问题与动机

提前退出模型允许部分 token 在中间层直接生成，但不同请求的退出层不同：有些 token 仍需执行较深的层；如果为所有请求常驻全部层，闲置权重也会占用显存，限制批处理规模。HELIOS 尝试同时减少执行层数与已加载层数（§1–2）。[^paper]

不同模型对于同一输入的退出分布可能互补，较难在一个模型中提前退出的请求，可能在另一个模型较早退出。系统利用这一经验选择模型，但输出模型也随之变化，不能视作对固定模型的无损加速（§3.1）。[^paper]

## 关键观察 / 隐含假设

- **请求流具有时间局部性**：近期观测到的退出层分布可指导接下来一段时间的加载，分布突变则可能使画像过时（§3.3）。[^paper]
- **退出置信度只是代理信号**：提前退出、切换模型和未达到阈值时继续输出都可能改变生成内容；困惑度与下游质量指标需要分别评估（§3.3、§5.4、附录 A）。[^paper]
- **增加 batch 需要可用显存**：减少加载层数可节省权重和对应状态，但动态加载、模型切换与内存池仍带来额外成本（§3、§5.8）。[^paper]

## 核心方法

### 候选模型和退出画像

系统先根据模型仓库中的性能、准确率信息及可用硬件选出候选，默认最多三个；再用实时请求评估候选的吞吐、困惑度和退出层分布，默认每个候选使用五个请求。论文让这些候选直接生成对应请求的输出，而不是将输出丢弃（§3.3.1–3.3.2）。[^paper]

画像选出模型后，系统贪心加载最可能需要的前若干层；若后续 token 未达到置信度阈值，则比较补加载当前模型的层与切换另一个候选模型的成本，并周期性重新评估（§3.3.3–3.3.4）。[^paper]

### 置信度违例与加载开销

系统不会在每次低于阈值时立刻补层或切换：它在窗口内累计违例，超过上限后再重新决策。默认窗口为 100 个 token、上限 50 次；因此部分 token 可能在未达到阈值时退出，阈值并非逐 token 硬保证（§3.3.3、§5.7）。[^paper]

为降低切换尖峰，原型使用预分配显存池，并在已有层计算时流水加载后续层。论文给出特定情况下加载额外四层约增加 4 ms 的例子，这不是任意模型切换的延迟上界（§5.8）。[^paper]

## 设计取舍

- **退出更早与质量**：少执行层、切换小模型或容忍置信度违例可能降低成本，也可能改变回答质量。
- **节省显存与动态加载**：只保留常用层有利于扩大 batch，但突发请求可能触发权重加载、切换和尾延迟。
- **重评频率**：频繁画像产生开销；间隔过长则难以及时适应请求分布变化。

## 实验与结果

作者基于 EE-LLM 实现，在四张 A100 40 GB GPU 的节点上测试 OPT 和 Llama 系列早退模型，使用 ShareGPT 及多任务混合负载；Llama2-70B 和 CodeLlama-34B 分别采用 TP 4 和 TP 2（§4）。[^paper]

| 结果 | 条件与边界 |
|---|---|
| 单请求吞吐 | 固定 batch 1 的混合任务实验中，相对单独使用 OPT-1.3B 和 OPT-6.7B 早退模型分别提升 1.48× 和 2.13×；不能直接当作多并发服务收益（§5.1、图 8）。 |
| 显存与 batch | 作者报告部分设置中 batch 提高最多 15.14×、显存占用减少最多 67.4%；是不同配置下的最大值，并非每个负载都达到（§5.3）。 |
| 加载与切换消融 | ShareGPT 上，默认配置吞吐为 138.5、困惑度为 1.62；仅切换、不补层为 142.9 和 1.65，说明吞吐与困惑度存在权衡（§5.7、表 8）。 |
| 下游指标 | 表 7 比较 ShareGPT、CNN/DM 和 HumanEval 的 ROUGE-2：HELIOS 分别为 0.098、0.097、0.058。HumanEval 的 ROUGE-2 不是代码执行正确率，不能据此证明代码语义等价（§5.4）。 |

## 批判性分析

### 论证链条

方法从跨模型退出互补与退出分布局部性出发，结合部分加载、动态选择及重评；表 8 支持加载和切换之间存在吞吐—困惑度权衡，但不证明所有应用都能接受这一质量差异。[^paper]

### 假设压力测试

当请求类型突变、少见任务连续出现或长期低置信度输出时，旧画像可能导致反复加载与切换。CBC 聚合窗口又允许一部分低置信度 token 直接输出，因此高风险任务应单独限制可用模型、退出策略并验证质量。[^paper]

### 实验可信度

作者同时报告吞吐、显存、困惑度和若干 ROUGE-2，但多数质量指标无法覆盖复杂推理或代码正确性；同一问题可能由不同候选模型回答，服务也需明确模型身份及输出一致性要求。[^paper]
