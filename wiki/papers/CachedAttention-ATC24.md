# 面向多轮对话的 CachedAttention（ATC 2024）

> **原题**：Cost-Efficient Large Language Model Serving for Multi-turn Conversations with CachedAttention

> **一句话总结**：CachedAttention 将非活跃会话的 KV cache 保存在 CPU 内存和 SSD，通过队列感知的分层放置与逐层异步搬运减少下一轮重算；在论文的 ShareGPT 工作负载和四种模型上，相对每轮重算的基线，TTFT 降低 61%–87%，但上下文截断后的 KV 复用不等同于对截断文本重新计算。

**资料来源**：ATC 会议版 PDF，使用文本提取辅助核对。MinerU 服务不可用，尚无对应的 MinerU Markdown 与图片。本文图表和数字均以会议版为准。[^paper]

## 问题与动机

多轮对话的下一条请求通常包含之前的提问和回答。如果服务在一轮结束后释放 GPU 中的 KV cache，下一轮就要对历史 token 重新 prefill；对话越长，重复计算越多。论文对 ShareGPT 的分析称 73% 的会话有多轮；在较晚的轮次，历史 token 和其重复计算可占 prefill 的绝大部分（§2.3、图 2、图 4）。

保留所有会话的 KV 又会迅速占满显存。论文以四张 A100 运行 LLaMA-65B 为例，2K token 产生约 5 GB KV，按其测量的生成速度，约 190 GB 可用显存约 14 秒就会填满。CPU 内存容量更大，SSD 能容纳更多会话，但它们和 GPU 之间的访问成为新的瓶颈：同一设置下，计算 2K token 的 prefill 约需 360 ms，从主存搬回对应 KV 约需 192 ms（§2.4）。

作者将问题拆为四项：如何隐藏显存与主存之间的搬运；如何用主存和 SSD 提供足够容量；如何让即将运行的请求尽可能命中主存；上下文超长截断时如何继续复用已有 KV（§1、§2.4）。CachedAttention 是执行复用的方案，AttentionStore 是其分层 KV 存储组件（§3.1）。

## 关键观察 / 隐含假设

- **观察 1：多轮对话中，同一历史前缀可能在多个轮次反复计算。** 作者分析的 ShareGPT 会话中 73% 有多轮，图 4 展示了随轮次增加的历史 token 和重复 prefill 成本（§2.3）。
  - **依赖假设**：后续轮次确实保留了相同历史，且会话可在缓存淘汰前再次到达；单轮请求、频繁改写历史或很低的复访率会削弱收益。
- **观察 2：从主存加载历史 KV 与新 token 的逐层计算存在重叠机会。** 模型按层执行，后一层的历史 KV 可以在前一层计算时加载（§3.2.1、图 6–7）。
  - **依赖假设**：主存、PCIe 与 GPU 资源允许并行，且提前量和缓冲足以覆盖搬运；历史很长而新输入很短时，加载可能超过可重叠计算时间。
- **观察 3：等待队列提供已到达请求的未来访问信息。** 缓存管理器可据此提前搬运队列中请求的 KV，并优先保留靠近队首的会话（§3.3、图 9）。
  - **依赖假设**：请求在队列中等待足够长，队列顺序相对稳定，且 SSD 有空闲带宽；队列很短、突发到达或频繁调整优先级时，预取可能来不及或产生额外 I/O。
- **观察 4：上下文截断会改变保留 token 的位置编号。** 论文对相对位置编码的处理是在保存前分离位置编码，加载后再按新位置应用（§3.4、图 10–12）。
  - **依赖假设**：模型的位置编码可在所用实现中这样分离；并且实验任务对保留 KV 中来自已删除上下文的影响足够不敏感。位置重新编码本身不保证与截断后重新计算逐项相等。

## 核心方法

### 1. 跨轮复用与 AttentionStore

一轮结束后，CachedAttention 保存该会话历史 KV；下一轮到来时加载它，只对新增输入执行 prefill。AttentionStore 在 CPU 内存和 SSD 中以块管理缓存；CUDA stream 负责 GPU 与主存间搬运，独立 I/O 线程负责主存和磁盘间迁移。论文本机实现使用 PyTorch、Python 和 Transformers，开启连续批处理（§3.1、§4.1）。

这是以会话为对象的历史复用：下一轮若找不到所需缓存，仍需重新计算。论文的 SSD 路径服务于非活跃会话的跨轮恢复，不能直接当作活跃长上下文 decode 每步从 SSD 读取 KV 的设计。

### 2. 逐层预加载与异步保存

**读取**：计算当前层时，将后续层的历史 KV 从主存异步加载到显存。预留显存读缓冲后，下一个任务可在前一个任务结束之前开始预加载；如果单层加载时间长于当前层新输入的计算时间，则增加提前加载的层数和缓冲空间，仍可能存在无法隐藏的等待（§3.2.1、图 6–7）。

**写入**：prefill 阶段按层异步保存新生成的 KV，decode 阶段继续逐层写回；若本轮结束时尚未写完，将未完成的数据放入显存写缓冲，以便下一个任务开始执行。异步化需要维持缓冲区生命周期并在复用或释放前保证写入完成（§3.2.2、图 8）。

### 3. 用队列信息管理主存和 SSD

**预取窗口**：缓存管理器查看调度队列中即将执行的请求；若会话 KV 命中 SSD，则在执行前异步搬入主存。窗口长度按可用于预取的主存容量除以会话平均 KV 大小估算。主存预留缓冲，并在空闲空间降至阈值时触发降级，避免磁盘回载找不到空间（§3.3.1）。

**淘汰窗口**：主存不足时，依据队列中的相对位置选择较晚使用的会话降级到 SSD；整个存储系统不足时，尽量保护淘汰窗口内将要使用的会话。论文的迁移与淘汰最小单位是整段会话 KV。该机制利用现有请求队列指导缓存放置，并未提出独立的请求排序算法；队列外的新请求不是已知的未来（§3.3.2、图 9）。

### 4. 位置编码解耦与截断

达到上下文长度限制时，常见做法是删除一部分旧 token，再对剩余文本重算 KV。CachedAttention 针对论文所述可分离的相对位置编码，在写入存储时保留尚未嵌入位置编码的 Key；截断时删除对应缓存，加载保留部分后按新位置重新应用编码。这样消除了直接复用旧位置编码带来的错位，避免仅为此重做整段 prefill（§3.4）。

但是，更深层的保留 KV 已由其原先可见的上下文计算得到，可能包含已删 token 的影响。位置编码解耦不能抹除这种依赖，因此不能据此断言与截断后从头 prefill 的 KV 或输出完全一致。作者测试 PPL 与任务准确率接近重算，是有限数据集上的质量证据，不是等价性证明（表 1–2）。

## 设计取舍

- **容量与搬运**：主存和 SSD 增加了可保留会话数，却带来磁盘写入、PCIe 流量和等待；读写缓冲也占用显存。
- **队列前瞻与预测范围**：等待队列提供真实的已到达请求信息，但不包含未来尚未到达的请求；会话级管理简单，也可能搬入之后不需要的部分。
- **截断效率与语义**：复用保留 KV 避免重算，但需要模型支持相应的位置编码处理，截断后的历史依赖和质量变化应单独评估。

## 实验与结果

**配置**：四张 80 GB A100、128 GB DRAM、10 TB SSD、PCIe Gen4；模型为 LLaMA-13B、LLaMA-65B、LLaMA-70B 和 Falcon-40B，激活为 FP16。ShareGPT 的 9K 会话平均 5.75 轮；由于数据集没有公开到达时间，论文用泊松过程合成到达，前 10K 轮预热、后约 42K 轮评估。主基线 RE 每轮丢弃非活跃会话 KV 并在下次重算（§4.1–4.2）。

- **端到端**：对上述四种模型，缓存总命中率依次约为 86%、71%、89%、90%；相对 RE，TTFT 分别降低 85%、61%、87%、86%，prefill 吞吐分别为 6.8、2.6、7.8、7.2 倍。LLaMA-65B 的 KV 每 token 约 2.5 MB，在固定容量下缓存的会话更少（图 13–15）。
- **完成时间和成本**：完成整个工作负载的 GPU 时间分别缩短至约 1/4.0、1/1.9、1/3.3、1/3.4；按论文给出的 AWS 按需单价估算，总成本分别降低 70%、43%、66%、68%。成本结论依赖 2024 年论文采用的 GPU、DRAM 和 SSD 单价及相同工作负载（图 16–17）。
- **搬运消融**：LLaMA-13B、单 A100、batch 16、历史 1K token 和新增 100 token 时，与不预加载相比，逐层预加载且无读缓冲使 prefill 时间降低 35%，15 层 KV 的读缓冲对应降低 61%；异步保存的实验使整体执行时间降低 13%–15%（§4.3.2、图 19–20）。
- **分层管理消融**：128 GB DRAM、10 TB SSD 下，队列感知策略总命中率为 86%，LRU 和 FIFO 分别为 58% 和 48%；作者说明后两者没有利用队列提前从磁盘预取，因此这组比较同时体现淘汰和预取差异，不能将全部收益归因于单独的替换策略（§4.3.3、图 21）。
- **截断质量**：WikiText-2 上，LLaMA-7B 的 CachedAttention PPL 为 5.47，截断后重算为 5.48；LLaMA-13B 在 MMLU 上分别为 52.3% 和 53.2%。朴素截断且不修正位置编码明显更差；这些结果不代表逐 token 等价（§4.3.5、表 1–2）。
- **容量敏感性**：作者以一小时 TTL 计算工作负载相关的容量尺度，在图 23 的测试中，实际缓存容量达到该尺度的 0.1 和 0.25 时命中率分别约为 51% 和 98%；它依赖该工作负载和定义，不能视为通用配置比例（§4.3.6）。

## 批判性分析

### 论证链条

论文从历史重算、存储容量、数据搬运和截断四个问题分别提出设计，并用端到端结果与消融支撑。主基线完全重算，能说明缓存相对重算的价值，但不能据此证明优于后来支持前缀共享的服务引擎。队列感知消融把预取与淘汰一起比较，也难以单独量化每一项。

### 假设压力测试

历史上下文占比高时，节省的计算更可能覆盖加载成本；短历史、快速 prefill、慢 SSD 或主机链路争用可能使复用不划算。会话级迁移和平均大小估算在长度分布高度不均时可能使缓冲和窗口利用不足。未来请求不可见，因此队列前瞻不等于预测所有后续交互。

### 实验可信度

ShareGPT 提供对话内容，但到达时间由泊松过程生成，用户思考时间及会话复访规律未由真实到达轨迹直接验证。论文覆盖多种模型、消融、成本和质量；结果依赖 A100、PCIe Gen4、固定批处理和当时的价格。论文未与当前引擎或新一代 GPU 进行比较，不宜直接外推。

### 系统性缺陷

异步写入和跨层迁移需要处理并发访问、缓冲回收与恢复；论文没有充分评估进程或设备故障下未完成写入、租户间隔离，以及 SSD 长期写入与共享带宽干扰。截断结果需要特别区分任务级质量接近和计算语义完全一致。

## 局限与后续工作

- 在真实多轮访问时间轨迹下测量队列长度、预取命中率、SSD 排队和 P95/P99 TTFT，比较缓存加载与直接重算。
- 对截断后的保留 KV 与重新 prefill 的 KV 做逐层差异分析，并在需要旧信息的任务上测量输出差异。
- 在不同 PCIe、SSD 带宽及新模型的 GQA 配置下重测搬运交叉点和显存缓冲成本。
