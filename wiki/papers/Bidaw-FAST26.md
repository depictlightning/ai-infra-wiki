# Bidaw：协同计算与存储的多轮对话 KV 缓存（FAST 2026）

> **原题**：Bidaw: Enhancing Key-Value Caching for Interactive LLM Serving via Bidirectional Computation–Storage Awareness

> **一句话总结**：多轮对话的历史 KV 会在主存和 SSD 间反复访问，Bidaw 根据缓存位置调度请求，并利用上一轮回答长度辅助替换；在作者的多模型自有负载实验中，相同延迟下支持的用户到达率提高 1.43–1.83 倍（§5.1、图 15）。[^paper]

**阅读状态**：已阅读会议正式版的 MinerU 全文，并核对系统结构、主要结果、替换策略和消融图；结论限定在论文报告的工作负载与硬件条件内。[^paper]

## 问题与动机

交互式服务的用户请求之间可能间隔较久。每轮结束后，GPU 中的历史 KV 可以被释放；下一轮若不缓存就要重算历史。论文研究用主存作为性能层、SSD 作为容量层的两级缓存，加载历史数据处于响应关键路径（§2.1）。[^paper]

在作者的多轮对话负载中，平均每个用户交互 22.4 轮；所测 OPT-13B、30 个新用户/分钟情况下，80% 的加权复用距离超过 200 GB 主存缓存。这个工作负载不能直接推广到所有聊天或 agent 服务（§2.2、图 4、图 6）。[^paper]

## 关键观察 / 隐含假设

- **冷热请求的加载时长不同**：来自主存和 SSD 的请求混在先进先出队列中，长时间读取可能阻塞已准备好的请求。收益依赖两级存储有足够大的访问时间差（§2.2–2.3）。[^paper]
- **上一轮回答长度提供交互时间线索**：作者对 12 组轨迹测量，回答长度与加权复用距离的下界的 Spearman 系数为 0.94–0.98；这不是回答长度与每次实际复用距离都具有同样相关性（§3.3、图 12）。[^paper]
- **该线索依赖用户行为**：公开 ShareGPT 数据没有时间戳，作者用泊松分布模拟后，上一轮回答驱逐策略未再降低未命中率；因此不能假定生成长度在所有负载中都有效（§5.3）。[^paper]

## 核心方法

### 感知 I/O 的请求调度

请求的历史张量位于主存时进入就绪队列；位于 SSD 时进入准备队列，预取到主存后再晋升就绪队列。就绪队列按原始到达时间排序，显存装不下的请求可以被跳过；准备队列根据等待时间和历史张量大小计算优先级，让短读取优先，同时逐渐提高长请求的优先级。这样可避免慢 I/O 阻塞已经准备好的请求（§3.2、图 10–11）。[^paper]

### 根据回答长度辅助缓存替换

系统基于历史轨迹维护后台模拟缓存，对不同加权复用距离区间估计命中潜力。它结合上一轮回答长度预测复用距离下界，并优先淘汰估计命中潜力较低的内容。后台使用已经发生的轨迹计算参考，并不意味着在线系统能够知道真实未来（§3.3）。[^paper]

### 选择更节省空间的中间张量

作者比较保存各层中间张量时的空间与节省的计算，OPT-13B 的归一化激活比直接保存 KV 更节省空间；命中后再转换成 KV。转换利用低优先级 CUDA 流，节省存储同时增加部分计算。论文指出对于 GQA，KV 较小，直接保存 KV 更合适（§4、图 14）。[^paper]

此外，历史和当前问题采用较大的 GPU 内存块以提高 CPU–GPU 传输效率，尚不知道长度的回答采用较小块；大块可以拆分、小块可以合并，缓解碎片（§4）。[^paper]

## 设计取舍

- 用更多调度信息减少阻塞，但维护两个队列、预取和后台模拟缓存会引入额外状态与管理开销。
- 缓存中间激活可减少空间，恢复 KV 则需要 GPU 计算；设备繁忙时该计算不一定能完全隐藏。
- 用户行为是预测依据；真实交互节奏变化或合成时间戳可能破坏这一关联。

## 实验与结果

作者使用一张 80 GB A800、200 GB 主存和由四块 SATA SSD 构成的 RAID-5，测得 SSD 带宽为 1.5 GB/s；评测 OPT-6.7B、OPT-13B、OPT-30B、Qwen-7B 和 Qwen-14B（§5）。[^paper]

| 结果 | 条件与比较 |
|---|---|
| 响应延迟最高降低 3.58 倍 | 作者负载，OPT-13B；对照包括 CachedAttention、FlashGen（§5.1、图 15）。 |
| 用户到达率提高 1.43–1.83 倍 | 在近似响应延迟下与已有方案比较，不应解释成固定请求率下延迟提高相同倍数（§5.1）。 |
| ShareGPT 支持的用户到达率提高 1.40 倍 | OPT-13B；FlashGen 和 Bidaw 的平均延迟分别为 9.09 s、8.70 s，时间戳由泊松分布模拟（§5.3、图 17）。 |
| 平均排队时间从 5.76 s 降至 2.45 s | OPT-13B、30 个新用户/分钟，比较 I/O 感知调度与先进先出（§5.5、图 19）。 |
| P99 降低 47.03% / 56.81% | OPT-30B，分别对比 CachedAttention / FlashGen（§5.8、图 22）。 |

作者逐项加入 I/O 感知调度、回答长度驱逐和中间张量缓存，报告各项在对应条件下有额外收益；不能直接把不同消融点的倍数相乘作为其他负载的预测（§5.7）。[^paper]

开销实验中，每次调度平均 0.62 ms，前一回答驱逐操作平均 0.35 ms，后台最优策略模拟平均 2.86 ms；这是 OPT-13B、每分钟 30 个新用户下的测量，不代表高并发部署的固定成本（§5.6、图 20）。[^paper]

## 批判性分析

### 论证链条

加载时间差解释了队头阻塞，用户阅读间隔解释了替换线索；调度、驱逐和张量选择的消融提供了分项证据。两个观察分别依赖存储和用户行为，不能把一种负载上的整体收益直接归因于某一个组件。[^paper]

### 假设压力测试

自动化 agent 请求、批量提交或多用户共享前缀可能没有相同的人类阅读间隔。若 SSD 带宽更高或主存缓存足够大，I/O 感知调度空间也可能缩小。论文用模拟 5 GB/s SSD 的方式测量，但这不等同于真实设备的完整 I/O 行为（§5.1、§5.3）。[^paper]

### 实验可信度

论文同时给出自有轨迹和公开数据的结果，并披露公开数据时间戳的限制。CachedAttention 和 FlashGen 均为作者基于 vLLM 的复现版本；模型和硬件集中在单 GPU，多节点、多租户的公平性和尾延迟需要另外验证。[^paper]

### 系统性缺陷

缓存状态、预取与后台模拟增加系统复杂度。恢复所存中间张量会占用 GPU，论文只在所测设置中报告转换开销；跨租户隔离和实际部署成本仍需评估。[^paper]

## 局限与后续工作

- 对真实 agent 调用、多轮人类对话和泊松时间戳分别重放，比较回答长度与真实间隔的相关性及各替换策略的命中率。
- 在更快 SSD、多 GPU 和不同主存预算下测量请求 P99、公平性与单位请求的重算成本。
