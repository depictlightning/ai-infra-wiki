# SolidAttention：面向内存受限个人电脑的 SSD 推理（FAST 2026）

> **原题**：SolidAttention: Low-Latency SSD-based Serving on Memory-Constrained PCs

> **一句话总结**：本地单请求推理难以用其他请求的计算掩盖 SSD 读取，SolidAttention 联合设计稀疏注意力的数据布局、预测预取和任务调度；在 RTX 4070 Laptop、128K 输入和 Llama-3.1-8B 上，吞吐是同样采用 SSD 卸载与稀疏注意力的基线的 3.1 倍（§8.1–8.2、图 12）。[^paper]

**阅读范围**：基于仓库中会议正式版 PDF 的 MinerU 全文，核对块布局、单层时间线、预取纠错、DAG 调度与评测，回看图 4、5、7、10、12、16、17、20 和表 1。性能数字是作者在指定设备与工作负载上的报告；未复现实验。[^paper]

## 问题与动机

长上下文的完整 KV cache 可能超过个人电脑可用内存。把历史 KV 放入 SSD 后，动态稀疏注意力可以只加载部分历史，但它产生大量细粒度、位置不规则的读取；SSD 更适合较大的 I/O。单用户、批次为 1 时，又缺少并发请求的计算来掩盖读取等待（§1–2）。[^paper]

论文处理的对象是低并发本地推理，而非以多 GPU 集群吞吐为目标的服务。它借用 InfLLM 的块级选择，并将完整历史放在 SSD 上；选择出的块才进入注意力计算。和 [[HiSparse-arXiv26]] 的主机内存分层不同，SSD 的延迟、带宽和后台 I/O 争用更直接决定收益。[^paper]

## 关键观察 / 隐含假设

- **观察 1：SSD 传输粒度与稀疏选择粒度存在冲突。** 图 1 显示小随机读难以利用 SSD 带宽；图 6 中 PassageRetrieval 的块大小从 32 增到 256 token 时召回率下降（§2–4）。[^paper]
  - **依赖假设**：同一批 K/V 可以按交错布局传输，且预拼接权重与步长访问的代价低于节省的 I/O。模型布局、设备和选择粒度不同，需要分别验证性能与质量。
- **观察 2：相邻生成步骤的块选择具有局部性。** 作者在所测模型与 LongBench 任务上观察到相邻步骤的选择约有 81% 相似度，并据此前置同层上一轮的读取（§5、图 9）。[^paper]
  - **依赖假设**：待预测层的历史选择对当前请求足够稳定，且 SSD 和 GPU 有空闲窗口。选择快速变化时需要补读更多块、错误预取也会占带宽；纠错保持的是当前稀疏选择，而非完整注意力。
- **观察 3：SSD 后台负载会显著影响吞吐。** CUDA 实验中，4 GB/s 后台顺序读使吞吐下降 58%；800K IOPS 的随机读使其下降 54%（§8.6、图 20）。[^paper]
  - **依赖假设**：预取时仍有可用 SSD 带宽，系统的目标延迟容许实际 I/O 排队。多任务争用和不同 SSD 下，论文的无干扰结果不能直接外推。
- **观察 4：细粒度异步操作会产生同步开销。** 图 17 中分别测试了细粒度重叠与同步点复用，对所测 SYCL 配置的注意力延迟均有改善（§6、§8.4.4）。[^paper]
  - **代价假设**：任务依赖和共享缓冲区冲突被正确建模，同步可以安全合并；算子本身更重或设备同步开销更低时，合并收益可能较小。

## 核心方法

### 块选择与交错布局

每层将历史分成初始块、最近的局部块和动态选择块。初始与局部块保证参与注意力；其余块用 K 的代表向量与当前 query 计算相似度，再取 top-k（§3.1、图 4）。这是一种近似注意力，完整 KV 仍保存在 SSD，稀疏选择本身可能影响输出质量。[^paper]

KV consolidator 将每个 token 的 K、V 交错存储，形成更大且连续的传输单位；权重预拼接让新 KV 直接按该布局产生。计算侧通过步长访问分开的 K、V，避免为每次读取重排数据（§4）。[^paper]

为什么不直接把选择块做大？每个块只能用有限的代表信息概括内容，论文在 PassageRetrieval 上观察到块从 32 增至 256 token 时召回下降。交错布局保持原有选择粒度，把同一组 token 的 K 和 V 连续放置：一次传输携带两者，论文估计传输单位扩大一倍、I/O 次数减半。模型初始化时预先拼接 K/V 投影权重，新输出直接符合交错格式；计算时以固定步长读取，论文所测算子开销不超过 2%（§4、图 6–8）。这改善的是 I/O 组织，不代表稀疏选择变成了完整注意力。[^paper]

### 预取与计算调度

预取器根据前一次同层选择预测本次动态块，并提前读入；实际选择出炉后，未命中块再从 SSD 加载，错误预取的槽可直接覆盖。注意力对所选 KV 的排列顺序没有要求，这降低了纠错时的数据重排开销（§5、图 10）。[^paper]

例如上一轮某层选择了块 4、6，本轮先连同确定需要的初始块和局部块预取；当前 query 真正算出选择后，如果需要的是块 4、3，就保留块 4，把块 6 的槽覆盖为新读入的块 3。K 与 V 仍须按 token 对齐，已有位置编码等信息也须正确保留；论文利用的是对**已选 KV 对的排列**不敏感，而不是可以随意打乱 K/V 对应关系。错误预取会浪费读取带宽，缺失块补读仍在当前注意力的依赖路径上。[^paper]

预测与近似是两件事：预取预测错了会用当前轮选择结果补齐，因而不改变这轮稀疏选择所规定的输入；但当前轮的 top-k 块本身就省略了其他历史，对完整注意力而言仍是近似。论文在所测 LongBench 工作负载上观察到相邻轮次选择约有 81% 相似度，这只是该组实验的统计，不保证所有层和任务都达到同一命中率（§5、图 9–10）。[^paper]

SSD-aware scheduler 将投影、块选择、预取、加载及注意力拆成有依赖的任务，尽可能重叠 GPU 计算与 I/O；非关键任务复用关键路径上的同步点，减少额外同步。共享缓冲区的读写仍需遵守依赖，否则预取可能覆盖尚未消费的数据（§6、图 11）。[^paper]

单层时间线中的主要依赖可以写成：

1. 先将该层预测块从 SSD 经主机读入 GPU；query 投影完成后，运行正式块选择。
2. 对选择遗漏的块发起补读，同时 GPU 计算当前 token 的 K/V 投影；新 KV 随后经过主机准备写回 SSD。
3. 当前层注意力等待真正需要的块就绪；在注意力计算期间，下一层预测块可从 SSD 读入主机。
4. FFN 执行期间，再将下一层预取数据送往 GPU，并写回本层新 KV；数据依赖和缓冲区复用限制哪些操作能够并行（§3.2、图 5）。[^paper]

论文用 DAG 表示投影、选择、补读、注意力及写回的依赖，通过反向遍历估计任务的最晚开始时间：优先运行就绪的关键路径任务，其次尽早启动 I/O。被选块预取关系到后续纠错，可以优先于初始和局部块的传输。同步点复用则把不在关键路径上的工作与必需的设备同步合并，减少握手次数；它依赖依赖图正确表达共享缓冲区冲突，并非取消同步（§6、算法 1）。[^paper]

### 实现和默认预算

系统基于 llama.cpp，使用 liburing 发起 SSD I/O；论文报告一个 CPU 核负责 I/O、另一个核负责 SSD 与 GPU 协调。为了降低新 KV 小写入带来的写放大，系统为每层设置 32 KB 写缓冲，再批量写入 SSD。这个缓冲也是容量和数据持久性协议的一部分；论文提到减少磨损，但没有提供长期 SSD 寿命实验（§7）。[^paper]

实验中输入少于 4K token 时，注意力上下文预算取输入长度的 25%；更长输入使用 1K token 预算，其中一半分给初始和局部块，另一半分给动态选中块，选择块大小为 32 token。完整历史仍在 SSD，预算约束的是一次注意力所用上下文，并不是整个请求在 SSD 上最多只保存 1K token（§7）。[^paper]

## 设计取舍

- **容量换 I/O**：完整历史从内存迁出，设备内只保留有限上下文预算和代表向量；代价是 SSD 访问、存储空间及对后台 I/O 的敏感性。
- **稀疏近似换计算与数据搬运**：默认长输入仅选约 1K token 的上下文预算。基准准确率接近原始模型并不证明所有长文任务或模型都无损（§3.1、§8.3）。[^paper]
- **提前读取换预测错误成本**：预取错误时需要补读；是否值得预取取决于局部性和空闲带宽。

## 实验与结果

作者在两台 Linux 笔记本上评测：CUDA 设备为 RTX 4070 Laptop 8 GB，SYCL 设备使用 Intel Arc 140T 集显；两者均配备 64 GB DRAM 和 Samsung 990 PRO SSD。端到端测试将 DRAM 用量限制为 16 GB，batch 为 1、输出上限 512 token；权重为 INT4，KV 为 FP16（§8.1–8.2）。[^paper]

| 指标与范围 | 基线及结果 |
|---|---|
| CUDA，128K 输入 | 对比同样采用稀疏注意力和 SSD 卸载的 Offload+Sparse，Llama-3.2-3B、Llama-3.1-8B、Qwen-2.5-7B 分别达到 2.8、3.1、2.4 倍吞吐（图 12）。 |
| SYCL，128K 输入 | 同三模型分别最高达到 2.1、2.5、1.9 倍吞吐；这是另一硬件平台上的比较（图 13）。 |
| KV 内存占用 | 三个模型的 KV 内存用量分别缩小 61.9、62.0、61.9 倍；完整 KV 仍需 SSD 存储，代表向量也需额外空间（图 14）。 |
| I/O 消融 | 与不使用预取比较，预取减少 SSD 加载阻塞；CUDA 和 SYCL 上的最大降幅分别为 3.9 倍和 3.1 倍，具体收益依模型不同（图 16）。 |
| 组件消融 | 在所测 CUDA 设置中，交错 KV 使注意力延迟最多下降 22%；SYCL 上细粒度重叠和同步点复用分别带来额外改善，幅度依模型和对照阶段而异（图 17）。 |
| 模型质量 | 三个模型均采用 INT4 权重；Llama-3.1-8B 的 LongBench 汇总分数中，原始系统为 46.75，SolidAttention 为 45.35，INT4 KV 对照为 44.58。平均值不能说明每个子任务都不受影响（表 1、§8.3）。 |
| 资源争用 | 4 GB/s 后台读使系统吞吐下降 58%；比较 SSD 型号时，在 4K 上下文预算下较慢 SSD 的尾延迟增加 45%（图 19–20）。 |

### 稀疏近似与质量评测

表 1 的三组模型使用相同 INT4 权重，主要比较原始 llama.cpp、将 KV 量化到 INT4 的对照，以及采用 FP16 KV 与稀疏选择的 SolidAttention。以 Llama-3.1-8B 为例：[^paper]

| 指标 | 原始系统 | INT4 KV | SolidAttention |
|---|---:|---:|---:|
| MMLU | 65.91 | 62.93 | 66.16 |
| GSM8K | 81.25 | 76.56 | 80.69 |
| LongBench 汇总 | 46.75 | 44.58 | 45.35 |

LongBench 使用八个数据集，覆盖单文档、多文档问答与摘要等任务，长度最高到 64K；吞吐图的 128K 输入不等于在 128K 上完成了同样的质量验证。SolidAttention 某些分数略高于原始系统也不代表稀疏计算理论上更准确；任务抽样、生成和评价方式都可能影响结果，论文没有给出逐请求等价性保证（§8.2–8.3）。[^paper]

### 从消融看优化的来源

图 16 在 16K 输入下分别移除预取并统计加载阻塞；图 17 则在相应设备上拆出交错布局、细粒度重叠及同步复用。这些实验支持三类机制分别减少一部分等待，但指标是阻塞或注意力延迟，不能把它们的最大百分比直接相乘得到端到端吞吐。Qwen-2.5-7B 的 KV 较小而 FFN 更重，减少 I/O 在总时间中所占比例也会较低（§8.4）。[^paper]

同论文的 58.9 倍结果对比的是扩展支持 Llama/Qwen 的 FlexGen、16K 输入；它与上述 128K 同稀疏基线的 3.1 倍不是同一比较。论文在内存驻留的对照中报告吞吐最多降低 11%，这是对应实验设置下的比较，不能抵消 I/O 争用下的负结果（§8.2、§8.4）。[^paper]

## 批判性分析

### 论证链条

论文先识别小批次下难以掩盖的 SSD 读等待，再分别改善布局、发起时间与计算重叠；消融覆盖三个组件。相比把整体增益归因于单个预取器，这条链更能解释为何块布局和同步方式也会影响结果。[^paper]

### 假设压力测试

如果后台任务持续占用 SSD，预取与需求读取会争夺带宽；图 20 已显示显著退化。更长输出、并发请求及更大模型会改变计算与 I/O 比例，当前 batch 1、最多 512 输出 token 的测试不足以预测这些场景。[^paper]

### 实验可信度

同一稀疏卸载基线有助于隔离系统优化，但两套笔记本配置与三个模型不能覆盖全部设备。权重 INT4 和 KV FP16 必须分开理解；论文的质量评测也无法证明对每个任务都完全等价于全注意力。[^paper]

### 系统性缺陷

引入 SSD I/O、异步任务和跨设备同步增加实现与排障复杂度；论文对长期写入寿命、跨用户隔离及多任务公平性的覆盖有限。[^paper]

## 局限与后续工作

- 固定上下文预算限制可访问的历史范围；需要在长文检索、代码仓库与多轮对话上测量质量和缓存选择错误。
- 在相同 SSD 上加入不同持续时间及强度的后台读写，记录 P95/P99、吞吐和预取浪费，验证带宽争用下的策略边界。
- 将完整 SSD 占用、预取流量和能耗与 [[HiSparse-arXiv26]] 这类主机内存分层方案在相同模型、上下文和硬件条件下比较。
