# BOute：联合优化异构模型路由与 GPU 部署

> **原题**：BOute: Cost-Efficient LLM Serving with Heterogeneous LLMs and GPUs via Multi-Objective Bayesian Optimization

> **一句话总结**：在预算约束下联合选择请求路由阈值、模型副本部署和并行策略，以权衡输出质量与服务延迟。[^paper]

**阅读状态**：已阅读会议正式版 MinerU 正文及文内附录，核对设计图、主实验和消融；部分实验阈值与百分比描述不一致，暂标待复核。会议页面未列独立补充材料。[^paper]

## 问题与动机

小模型处理简单请求可能更省成本，大模型处理困难请求可能有更高质量；不同 GPU 的成本、显存和模型服务性能也不同。如果路由比例改变，但资源分配没有同步变化，某类模型可能成为瓶颈。BOute 将模型路由与异构资源部署放在一起优化，而非只优化其中一项（§1、§3）。[^paper]

## 关键观察 / 隐含假设

- **请求路由影响负载**：路由阈值改变各模型接收的请求比例，也改变各副本的排队和计算需求。
- **平均质量不是逐请求保证**：整体任务得分满足阈值不代表每次路由都选对模型，质量还依赖路由器和评估代理。
- **离线画像具有时效性**：候选配置的延迟来自画像与模拟；模型、输入输出长度、负载或设备变化可能使旧数据库失准。[^paper]
- **切换方案需要时间**：优化器收敛时间不包括完整的模型迁移、权重加载和副本滚动更新。[^paper]

## 核心方法

### 问题建模

输入包括可用模型、各 GPU 类型及数量、价格、请求与质量信息。优化变量包括按请求难度打分的路由阈值、模型到 GPU 的分配，以及数据、张量和流水线并行策略。目标是在资源与预算约束下寻找低延迟和高平均质量的 Pareto 解（§4）。[^paper]

### 离线画像与部署候选

系统画像 GPU 和请求长度，利用推理模拟器评估不同模型并行配置及负载；随后组合多个副本，搜索副本间负载分配，建立部署—负载—延迟数据库。不可容纳模型的配置被剪枝，候选通过 Pareto 筛选与背包问题缩小（§5.1–5.2）。跨 GPU 类型采用不同副本的数据并行，不是在同一副本内部混合不同 GPU 做张量并行。[^paper]

### 在线多目标搜索

在线阶段将路由阈值和部署候选交给多目标贝叶斯优化器，利用高斯过程代理模型及采集函数探索质量—延迟权衡。论文在代理模型中加入负载比例、输出变换及模型—GPU 偏好等结构信息；协调器据所选路由和副本分配发送请求（§5–6）。[^paper]

论文使用 Llama3.1-8B 和 70B，结合 H100、RTX PRO 6000、RTX 5090、RTX 4090，比较 GSM8K 和 MT-Bench；RouteLLM 基线使用均匀模型资源分配。部分候选性能来自模拟，主实验包含实际部署结果，不能把模拟器验证和全部线上条件等同。[^paper]

## 批判性分析

### 论证链条

论文先以服务瓶颈说明路由与资源需要协同，再用模拟数据库和贝叶斯优化降低部署搜索成本；均匀路由与同构 BOute 基线帮助分辨联合优化和硬件异构的作用。RouteLLM 基线固定均匀分配，结果不能推广成对任意经过资源优化的路由基线同等幅度的优势。[^paper]

### 假设压力测试

请求难度、长度和模型质量可能随时间一起变化。附录提出负载或质量分布变化时重新调度、长度变化时扩展数据库，但滚动更新是否避免延迟尖峰需要实际迁移实验支持；优化器的 23.5 秒不等于系统完全切换所需时间。[^paper]

### 实验可信度

作者报告实际 GPU 评测和模拟器抽样校验，但后者主要验证特定短输出下的吞吐；P95 与排队对流量突发和误差更敏感。正文质量阈值和示例降幅存在不一致，已在上表标出，不能直接将模糊数字作为精确结论。[^paper]

## 局限与后续工作

- 核对正文、图 4 和表 1 的质量阈值及示例比例，补充不同长度与突发流量下的 P95 模拟误差。
- 在公平优化资源分配的路由基线上评估，并测量迁移期间的额外 GPU 成本与尾延迟。
- 按实际业务验证路由误判、质量代理和请求分布漂移，而非仅依赖整体平均质量。
