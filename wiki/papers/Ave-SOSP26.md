# Ave：用数据流不变量引导智能体优化 GPU 内核（SOSP 2026）

> **原题**：Ave: Guiding Agentic GPU Optimization Using Data-Flow Invariants

> **一句话总结**：代码智能体会生成能跑的内核，却难以安全组合流水、共享内存布局和底层指令优化。Ave 让智能体声明“每个数据应来自哪里”之类的数据流不变量，由编译器在运行前给出违反证据，再让规划器继续改写；在 MI300X 的 GEMM、FlashAttention、MoE 评测中达到手工库 89–99% 的有效吞吐（摘要、§9）。

## 问题与动机

优化 GPU 内核需要同时协调访存布局、矩阵指令、软件流水和指令调度。单元测试只能告诉智能体输出是否错，性能剖析只告诉它是否慢，都很难指出“某个共享内存重排破坏了哪个逻辑元素的来源”。在论文的 MI300X 测试中，现有智能体生成的 GEMM 比 hipBLASLt 慢 1.8–14.3 倍（§1）。把所有底层选择交给高级编译器又限制了可探索的指令和布局空间。

Ave 的研究问题不是让 LLM 自己证明任意 CUDA 程序正确，而是给一组关键优化提供低成本、可定位的编译期约束。这个边界决定它仍需单元测试和基准测量，不能把“不变量通过”当作完整正确性证明。

## 关键观察 / 隐含假设

- **输出错误有结构性线索**：例如 attention 的 Q、K、V 在某次转置或分块后必须保留对应的逻辑坐标。若能沿数据流传播这些坐标标签，编译器可在消费点发现错配（§3–§5、图 1）。前提是人或智能体写出的标签表达了真正要守护的语义。
- **底层优化需要显式硬件控制，但不必暴露全部布局编码**：Ave 的 tile DSL 让智能体选硬件指令和编译策略，同时把复杂布局编码藏在 tile 抽象后（§4）。这使训练样例和知识库的可迁移性成为重要条件。
- **密集反馈比单一成功/失败更适合多步搜索**：编译期反例给出具体违反赋值，规划器可以把“哪一步破坏了不变量”纳入下一轮选择，而非只看最后测试是否通过（§5–§6）。

## 核心方法

Ave 的 DSL 将寄存器、共享内存和全局张量表述为 tile，并暴露低级指令与编译器策略。开发者或 lowering agent 用 tag 函数从逻辑坐标和表达式生成符号标签，再在读取、重排、归约等关键位置写 tag assertion；例如某个输出 tile 必须由相应 Q、K、V 坐标产生（§4、图 1）。标签代表数据来源关系，不是运行时张量内容。

编译器对中间表示做**流敏感、路径不敏感**的标签传播，再生成 SMT 约束检查 assertion。若抽象解释允许违规，求解器返回造成违规的具体标签赋值，帮助智能体修复；验证在编译期完成，不给最终内核增加运行时检查开销（§5）。路径不敏感让分析可扩展，也意味着复杂分支可能出现保守误报。它验证的是给定标签体系下的数据流关系，不验证算法本身是否选对、数值误差是否合规、死锁是否不存在。

优化循环包含两个角色：ICRL（上下文强化学习）规划器根据知识库选择下一项优化及对应不变量模板；lowering agent 将其实现为 DSL 代码与标签断言。每一轮先编译、查不变量、跑单元测试，成功后才做性能剖析；规划器用失败反例和速度反馈更新下一步计划（§6、算法 1）。这个次序避免大量明显错误的候选占用 GPU 测试时间，但仍要支付模型调用和编译成本。

## 设计取舍

- **局部可验证性换规范负担**：正确的 tag 断言能抓到数据混排；写漏断言或写错规范时，编译器只会忠实验证错误规范。
- **低级控制换 DSL 维护成本**：在 MI300X 优化得深，需要硬件特定指令、模板和知识库。迁往 H200 时仍需后端与样例适配。
- **路径不敏感换可分析性**：对控制流复杂、堆上指针关联或位级操作，静态标签不足以代替完整形式化验证（§5、§8）。

## 实验与结果

- **专家库对照**：MI300X 上针对 GEMM、FlashAttention、MoE，Ave 配合 GPT-5.6 Sol 达到手工高性能库 89–99% 的有效吞吐；相对未被训练数据污染的智能体基线，三类内核几何平均吞吐提升 1.62–1176 倍。区间跨度巨大，不能把 1176 倍解释为通常收益（§9、表 1）。
- **通用任务有效率**：在 KernelBench 200 项任务、提供 DSL 上下文例子的设置中，三次尝试内生成有效内核的比例为 Level 1 的 100%、Level 2 的 88%；这测的是有效性，不等于 200 项都达到专家性能（§9、表 3）。
- **消融与开销**：对知识库、ICRL 与不变量的组合做消融，论文报告不变量帮助侵入性布局与流水变换通过正确性检查；attention 不变量编译检查约 10–40 ms（§9、表 2、表 4）。最后运行的 GPU 内核无动态检查开销，但智能体搜索成本另计。

## 批判性分析

### 论证链条

论文把“优化搜索缺少定位反馈”映射成“把数据来源关系写成不变量，再生成反例”，设计与动机对应紧密。消融显示知识库、搜索顺序和不变量彼此配合，不能把所有性能提升都归于 SMT 检查。人工库 89–99% 是选定内核族的结果，不意味着对任意 GPU 程序都接近最优。

### 假设压力测试

若优化涉及数值近似、竞态时序、硬件资源死锁或未标签化的位级变换，数据流不变量可能无法表达真正风险。若模型或知识库已记住某个 benchmark 解法，性能对照也可能高估泛化；论文刻意使用“未污染”的智能体基线来处理一部分比较风险，但对新模型和新算子仍需复测（§8–§9）。

### 实验可信度

既给专家库吞吐，又给智能体基线、KernelBench 有效率和关组件对照，是比只展示单个成功内核更强的证据。1.62–1176 倍区间含极弱基线，报告时更应看绝对专家库比例。硬件主结果在 MI300X，硬件代际和编译工具链会影响结论。

### 系统性缺陷

不变量模板本身可能被优化智能体绕开，或者只覆盖已知错误形态；§8 也讨论 reward hacking。生产使用还需要单元测试、数值容忍度、资源占用和新输入形状审计。论文没有证明低级 kernel 的全功能正确性。

## 局限与后续工作

- 在未见过的硬件和模型算子上固定知识库与 token 预算，测有效率、性能及人工模板修改量。
- 构造“数据流标签正确但数值/并发错误”的反例集，明确 Ave 能保证什么、不能保证什么。
