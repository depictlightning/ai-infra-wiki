# TiDAR：扩散草稿与自回归验证共享一次前向计算

> **原题**：TiDAR: Think in Diffusion, Talk in Autoregression

> **一句话总结**：让经过适配的同一模型在一次前向计算中验证上一轮草稿，同时针对可能的接受长度并行准备下一轮扩散草稿，以减少生成轮次。[^paper]

**阅读状态**：已阅读会议正式版 MinerU 正文与附录，核对架构图、主结果和消融表；会议页面未列独立补充材料。[^paper]

## 问题与动机

单请求自回归解码往往受模型权重和 KV 读取限制，一次前向只产生一个 token。扩散语言模型可以并行预测多个位置，但直接并行输出可能损失 token 间依赖和生成质量。常规推测解码则需要先产出草稿、再验证，草稿阶段也可能有串行依赖（§1–2）。[^paper]

TiDAR 的切入点是在同一模型和同一次前向中重叠草稿与验证。它不是可以直接给任意原模型安装的无训练插件：作者从 Qwen 基座继续预训练模型，使其同时支持因果预测与扩散预测。[^paper]

## 关键观察 / 隐含假设

- **空闲计算空间有限**：低 batch、较短上下文和一定窗口大小时，增加前向计算的 token 可能只增加少量延迟；超过硬件容量或 batch 增大时，这个条件会改变（图 1、§5）。[^paper]
- **候选长度与成本要共同考虑**：每轮接受更多 token 可减少轮数，但为不同接受结果预先计算下一轮候选会带来额外计算。
- **精确缓存有前提**：已提交的因果前缀可保留 KV；草稿未通过验证的部分及临时掩码状态不能作为已提交历史复用。
- **质量接近不等于原模型无损**：继续训练后的 TiDAR 与原始 Qwen 参数不同；即使内部验证忠实于 TiDAR 自身的预测，也不能保证与原始 Qwen 输出一致。论文明确区分此方法与保留原始基座输出的推测解码。[^paper]

## 核心方法

### 双模式训练

TiDAR 使用共享模型参数，按结构化注意力掩码区分因果区域和扩散区域。训练时，对原始序列进行下一 token 预测，同时对附加的全掩码区域训练扩散预测；权重参数 $\alpha$ 控制两类损失。全掩码使每个扩散位置都有监督，并与推理时的一步扩散草稿相匹配（§3.1、图 3）。[^paper]

### 并行验证与预草稿

prefill 编码提示并产生首批草稿。之后每次前向同时处理上一轮草稿的因果验证，以及针对不同可接受前缀长度的一组掩码位置。验证完成后系统选取对应分支作为下一轮草稿；论文算法 2 中候选部分有 $K^2$ 个掩码位置和 $K$ 个草稿位置，因此扩大草稿长度并非没有成本（图 2、算法 1–2）。[^paper]

因果路径生成的 KV 暂存，拒绝的位置被丢弃，只保留已接受前缀。实现还会预先构造注意力掩码并按当前序列裁切，避免每一步重建。作者可混合自回归与扩散预测的 logits 进行验证；选择扩散或混合结果时，不能把输出理解为严格遵循原始 Qwen 的分布。[^paper]

## 实验与结果

作者从 Qwen2.5 1.5B、Qwen3 8B 继续预训练，分别使用 50B、150B 训练 token；推理效率测试主要使用单张 H100、batch=1。比较对象包括自回归模型、EAGLE-3 和 Block Diffusion；不同模型的训练与输出质量需要同时观察。[^paper]

## 批判性分析

### 论证链条

论文从低 batch 下的硬件利用不足出发，用共享参数与注意力掩码把草稿和验证放进同一前向，并以 token/前向、墙钟吞吐及任务质量共同评估。图 5 的框架实验补充了原生实现，但没有覆盖全部生产调度条件。[^paper]

### 假设压力测试

预计算不同接受长度的下一轮草稿，把可能浪费的计算换成较少串行等待。若并发较高、上下文较长或模型已接近计算瓶颈，额外掩码 token 可能显著增加前向延迟；应按实际 batch、长度分布和显存预算重新选择草稿长度。[^paper]

### 实验可信度

质量和速度基线并非完全相同：论文说明所测 EAGLE-3 使用 Qwen3-8B instruct 权重，而 TiDAR 的主要生成结果使用 base 模型。继续训练数据、模型版本及框架优化也影响比较；最高加速不能直接外推到现成线上服务。[^paper]

## 局限与后续工作

- 评测长上下文、不同 batch 和真实请求流下的延迟、吞吐及显存，并测试 CUDA graph 和优化内核对各基线的影响。
- 衡量额外继续预训练成本、模型质量变化和部署收益，区分忠于适配后模型与忠于原始模型。
- 验证不同接受长度下的注意力掩码与 KV 回收，避免未接受草稿进入后续上下文。
