# Buoy：面向分层前缀缓存的准入与替换策略（SIGMOD 2027）

> **原题**：Buoy: Efficient and Effective Cache Replacement for Prefix Caching

> **一句话总结**：Buoy 把前缀依赖、快速降级与分层命中位置纳入 GPU–CPU 缓存替换：新条目经深度感知准入后优先进入 DRAM，命中条目进入 HBM，并以访问位和幽灵缓存识别可复用项；在作者的 vLLM 顺序回放测试中，相对 LRU 的 prefill 吞吐提高 8%–16%（§3–5、图 10）。[^paper]

**版本与阅读范围**：依据《Proceedings of the ACM on Management of Data》2026 年 9 月正式发表的 27 页版本，DOI 为 `10.1145/3837101`；该文已被 SIGMOD 2027 录用，页面按会议年份命名。ACM 原 PDF 链接未能由解析工具直接读取，本地 PDF 来自 [DBScholar 的开放获取副本](https://upenn.ferric.systems/dbscholar/sigmod_papers/2027/263%20-%20Buoy%20Efficient%20and%20Effective%20Cache%20Replacement%20for%20Prefix%20Caching.pdf)，首页题名、作者、DOI、卷期与会议记录一致。PDF 按 1–20、21–27 页用 MinerU Flash 解析并合并；图像占位符和部分算法变量未完整抽取，已回看原 PDF 的图 6–10、15–16 和表 3–4。未运行作者代码或复现实验。[^paper][^accepted]

## 问题与动机

多轮对话、重复文档问答和智能体调用可能反复提交相同前缀。推理引擎把前一请求算出的前缀 KV 按块保存；后续请求匹配到已有块时，可以跳过这些 token 的重复 prefill。GPU 显存和 CPU 内存都有限，系统必须决定新 KV 是否值得保存、已有条目何时淘汰，以及热点应留在哪一层（§1–2）。[^paper]

传统缓存通常把每个条目的访问看成独立事件。但在前缀缓存里，访问较深的块需要先匹配它的所有祖先块；较浅的共同前缀也可能被多条后续路径共享。仅按单个块的最近访问时间淘汰，会忽略这种依赖（§3.1）。[^paper]

第二个问题是**总命中率与服务性能并不等价**。HBM 命中可由 GPU 直接使用；DRAM 命中虽然避免重算，却要先跨 CPU–GPU 链路加载。若算法把大部分命中留在 DRAM，命中率提升未必能带来相应的 TTFT 和吞吐收益。Buoy 同时研究保留哪些前缀，以及如何让更常复用的数据命中快层（§3.3）。[^paper]

## 关键观察 / 隐含假设

- **观察 1：可复用的深前缀依赖其祖先。** 图 4 构造 `[A,B,C]`、`[A,B,D]`、`[A,E,F]` 三条路径；在示例中，优先淘汰叶节点能保留更多共享祖先（§3.1）。[^paper]
  - **依赖假设**：相同祖先将被多条后续路径再次使用，保留它的价值高于被淘汰的叶节点。示例说明结构性机会，不证明浅层块在所有负载中都更有价值。
- **观察 2：基于复用的分段替换在所测轨迹优于 LRU。** 图 5 中 S3-FIFO、SLRU 的平均命中率分别达到 LRU 的 1.06、1.04 倍（§3.2）。[^paper]
  - **依赖假设**：单次访问的数据较多、重复访问有可利用的倾斜，早期降级不会过度淘汰稍后才复用的块。收益随轨迹和容量变化。
- **观察 3：总命中相近时，命中所在层可能差别很大。** 在图 5 所测 S3-FIFO 队列映射中，不到 1% 的命中发生在 HBM，大部分发生在 DRAM（§3.3）。[^paper]
  - **依赖假设**：HBM 命中节省的传输和等待足够明显，值得为提升快层命中调整替换顺序。实际效果还取决于 CPU–GPU 带宽和排队；该比例不是所有 S3-FIFO 实现的属性。
- **观察 4：前缀深度和重访可作为准入信号。** Buoy 根据观察到的复用深度维护阈值，并允许幽灵队列中再次出现的深节点进入缓存；论文评估了相应策略的消融（§4.3、§5.8）。[^paper]
  - **依赖假设**：既有复用深度对未来有一定预测力，且幽灵记录能捕捉重要重访。工作负载阶段性变化、旧浅前缀不再使用或新深热点突发时，累计均值可能适应较慢；这是基于算法的推断。
- **观察 5：真实 KV 仍需要慢层空间和加载。** 基础实现把候选块保存在主机内存，SSD 扩展进一步使用真实 SSD 缓存，而非仅保存幽灵 ID（§4.2、§5.6）。[^paper]
  - **代价假设**：主机容量、带宽和 SSD 写入预算能够满足缓存规模。多租户、NUMA、写放大或后台争用未在主结果中系统覆盖。

## 核心方法

### 状态：两层真实缓存和一层幽灵记录

Buoy 的基础设计有三个组件（§4.1、图 6）：[^paper]

| 组件 | 保存什么 | 负责什么 |
|---|---|---|
| HBM 队列 `H` | 指向 GPU 上实际 KV 的前缀块节点 | 保留被复用的热块，命中后可直接供 GPU 使用 |
| DRAM 队列 `M` | 指向主机内存上实际 KV 的节点及访问位 | 暂存新块和从 HBM 降级的块，依访问位提供第二次机会 |
| 幽灵队列 `G` | 最近被淘汰或因准入策略拒绝的块 ID | 记录近期错过的候选，辅助识别重现的前缀；不保存 KV 本体 |
| 准入控制器 | 当前深度阈值及重用信号 | 判断新块进入真实缓存还是仅留下幽灵记录 |

幽灵命中不等于 KV 命中：它只能证明一个 ID 最近出现过，若真实 KV 已不在缓存中，当前请求仍要通过正常计算或已有可用副本得到 KV，之后才可能保存。默认幽灵队列可容纳 DRAM 队列条目数的 4 倍；条目只存 ID，但元数据开销仍需计算（§4.2、§5.8）。[^paper]

### 命中、降级与第二次机会

对于一次请求匹配的前缀块序列，Buoy 在每层队列中查找（§4.2、算法 1、图 7）：[^paper]

1. **缓存命中**：已有节点的访问位置更新到 HBM 队列头部，并设置访问位。DRAM 命中需将真实 KV 搬到 GPU；HBM 命中直接复用。
2. **缓存未命中**：经准入控制后，新保存节点进入 DRAM 队列头部；若其 ID 命中幽灵队列，设置访问位，为它提供后续保留机会。
3. **HBM 空间不足**：队尾节点降级到 DRAM 队列头部；基础两层设计不让尚未证明复用的新候选长期占用前缀缓存 HBM。
4. **DRAM 空间不足**：检查队尾节点。若访问位为真，清零该位并移回队首；否则淘汰其 KV，并把 ID 记入幽灵队列。

第二次机会类似 CLOCK 的访问位思想：它不永久保护数据，只延后一次被淘汰的机会。主机副本的异步写入也不是没有成本；作者说明该写出不在其请求的用户可见关键路径上，但并发时会消耗内存带宽与 I/O 资源。[^paper]

算法按从根到叶匹配前缀；为在队列中保留相对前缀次序，作者先暂时移走命中的节点，最后逆序将本次访问节点插入目标队列，使更深节点更接近队尾、较浅祖先更靠近队首。**这是队列中的替换偏好，不是对所有分叉路径的未来访问顺序做精确预测**（§4.2、算法 1）。[^paper]

### 按前缀深度决定准入

设某次复用到的前缀深度为 `d`。Buoy 对已观察到的复用深度维护累计平均值，用它形成深度阈值：新块不超过阈值时默认准入；更深的新块默认拒绝，并将其 ID 放入幽灵队列。如果该 ID 后续再次出现并命中幽灵队列，则允许它进入缓存，即使深度超过阈值（§4.3）。[^paper]

准入和淘汰处理不同问题：准入决定一次新计算的块是否占用真实缓存；替换决定空间不足时哪些现有块留下。采用累计平均不需要事先离线画像，但它对很久之前的复用事件仍保留权重；如果工作负载发生阶段性变化，适应速度和误拒绝的代价需要进一步测量。论文消融支持该方法在所测轨迹下有效，没有证明累计平均优于滑动窗口或其他估计器。[^paper]

### 从两层扩展到 SSD

§5.6 将基础层次扩展为 HBM、DRAM、SSD：从 DRAM 降级或被准入控制拒绝的块可以放到 SSD，SSD 层替代原先只保存 ID 的幽灵层。SSD 使用 FIFO；命中时先经过 DRAM 暂存，再提升到 HBM。为便于对照，实验给其他替换基线使用相同 SSD FIFO 和提升行为。这里的 SSD 保存**真实 KV**，与两层版本只存 ID 的幽灵队列不是同一对象。[^paper]

### 一次示意请求

假设请求依次匹配 `[A,B,C]`，其中 A 在 HBM、B 在 DRAM，C 不在真实缓存：A 可直接复用；B 要回载到 HBM；C 需要计算。系统更新 A、B 的队列位置，再判断新产生的 C 是否准入；如果 C 之前被淘汰而其 ID 仍在幽灵队列，该记录可以影响后续保留。此例只说明各状态的职责，不代表论文图 7 的原始请求序列，也不假定实际实现会跳过前缀依赖。[^paper]

## 设计取舍

- **快层命中换异步降级和元数据操作**：命中后可以避免慢层传输，但新 KV 写入 DRAM、队列维护和同步会消耗资源。
- **拒绝深前缀换较少污染**：降低一次性长后缀的占用；被拒绝的深块若很快复用，首次重访可能仍需重算。
- **幽灵记录换有限的历史视野**：只保存 ID 比保存完整 KV 便宜，但其容量、哈希与队列维护并非零成本；记录被挤出后无法提供同样的重访信号。
- **第二次机会换额外驻留**：访问位可减少误淘汰，也可能让已不再使用的块多占一轮空间。
- **按命中升级换迁移与竞争**：DRAM 命中本来就需要回载；提升为 HBM 驻留仍要与活跃请求、其他热点和显存预算竞争。
- **前缀复用保持既定模型计算**：淘汰缓存本身不会凭空近似 KV；未命中需要正确重算，模型、位置、输入及缓存身份匹配是复用前提。论文没有把不同实现的逐位一致性作为主要实验。

## 实验设置

作者实现了两套评估：**前缀 KV 缓存模拟器**按轨迹回放块访问、统计各层命中；**vLLM 0.15.1 实现**执行实际模型，比较 prefill 吞吐与 TTFT。不能把图 8 的模拟命中率当成线上系统的真实延迟（§5.1）。[^paper]

模型为 Llama-8B 与 Mistral-24B，分别使用 A100 40 GB 和 A800 80 GB，主机缓存各为 64 GB DRAM，CPU–GPU 为 PCIe 4.0 x16。主要 GPU 实验顺序回放真实轨迹：上一请求完成后才提交下一请求；因此请求内容来自真实轨迹，但原始到达并发与在线排队没有被复现（§5.2）。[^paper]

| 轨迹 | 块大小 | 请求数 | 来源与工作负载 |
|---|---:|---:|---|
| Qwen-A | 16 token | 43,058 | 阿里云百炼，两小时聊天服务采样 |
| Qwen-B | 16 token | 172,800 | 阿里云百炼，两小时 API 调用采样 |
| Moon-Conv | 512 token | 12,031 | Kimi，一小时会话采样 |
| Moon-Tool | 512 token | 23,608 | Kimi，一小时工具和智能体交互采样 |

命中率是论文按请求统计的平均缓存命中率；prefill 吞吐将**缓存命中的输入 token 和新计算的输入 token 都计入**。TTFT 给出平均值及 P90/P95/P99；顺序回放的尾延迟不是高并发队列下的在线尾延迟（§5.2）。[^paper]

## 实验与结果

### 两层：模拟器中的命中与真实引擎中的 prefill

- **缓存命中**：Llama-8B、Qwen-A、16 GB HBM + 64 GB DRAM 的模拟中，LRU 总命中率为 22.0%，Buoy 为 26.8%，提高 4.8 个百分点，约为原来的 1.22 倍。这个比例不能表述为提高 22 个百分点（§5.3、图 8）。[^paper]
- **Prefill 吞吐**：Qwen-A / Qwen-B 上，Buoy 对 LRU 的提高分别为 Llama-8B 的 10% / 16%，Mistral-24B 的 8% / 13%。分母是 LRU；这是包含缓存命中 token 的 prefill 吞吐，不能直接解释为 decode 输出速度（§5.4、图 10）。[^paper]
- **首 token 延迟**：Llama-8B 的 Qwen-A / Qwen-B 平均 TTFT，相对 LRU 分别降低至约 `1/1.11` 和 `1/1.19`；Qwen-B 的 P90/P95/P99 分别降低 15.4%/13.9%/7.2%。这些尾指标来自顺序回放，不包括原始在线并发排队（§5.4、图 9）。[^paper]
- **管理开销**：作者报告 LRU 替换记账平均约 0.4 ms/请求、Buoy 约 2 ms/请求；两者前缀查找均为几微秒。额外的队列、访问位、幽灵查询和准入操作不是免费的（§5.4）。[^paper]

### SSD：总命中相近时，快层命中仍不同

Llama-8B、16 GB HBM + 64 GB DRAM + 512 GB SSD 的模拟中，Qwen-B 上 S3-FIFO 的总命中率为 52.45%，Buoy 为 51.85%；但 HBM 命中率分别为 0.65% 和 45.94%。这组数据是说明**命中层次很重要**的直接证据，也表明 Buoy 在此设置下并非总命中率最高（表 3）。[^paper]

对应三层 vLLM 测试中，Buoy 在 Qwen-A 报告 15,210 输入 token/s、152 ms TTFT；Qwen-B 为 15,807 输入 token/s、58 ms TTFT。对比最强替换基线，吞吐分别高 2.3%、0.7%，TTFT 分别低 2.2%、2.7%。论文指出大 SSD 缓解容量缺口后，总命中率差距收窄；此时的较小收益不应与两层设置的最大收益混写（§5.6、图 14）。[^paper]

### 规模、粒度与消融

- **两 GPU**：在两张 A100 上顺序回放，Qwen-A 的 TP 平均 TTFT 从 LRU 的 131 ms 降至 Buoy 的 117 ms；DP 从 200 ms 降至 180 ms。Qwen-B 分别为 TP 52→45 ms、DP 73→61 ms；DP 各副本独立缓存，不能将这个单机两卡测试当作大规模集群验证（§5.7、表 4）。[^paper]
- **准入与访问位**：Llama-8B 模拟的 Qwen-A 上，关闭准入为 23.8%、关闭访问位为 26.7%、完整 Buoy 为 26.8%；Moon-Conv 对应 5.7%、8.8%、9.0%。这两项是分别去除单个组件的对照，不可把差值简单相加（§5.8、图 15）。[^paper]
- **幽灵容量**：Qwen-A 中幽灵队列从 0 倍增至 4 倍 DRAM 条目数，命中率由 22.5% 提至 26.8%；8 倍时图 16 为 25.8%，并非单调上升。Qwen-B 对应从 48.8% 到 50.4%、8 倍为 50.5%。论文选择 4 倍作为默认值（§5.8、图 16）。[^paper]
- **块与容量敏感性**：Qwen 轨迹从 16 token 合并为更大块后，所有算法命中率下降。容量测试还比较去重后总足迹的 0.1%、1% 及 DRAM/HBM 容量比 2、4；少数小缓存设置中 Buoy 与某些基线接近或略低，论文并未证明所有配置都领先（§5.5、图 12–13）。[^paper]

## 批判性分析

### 论证链条

论文从前缀依赖、快速降级和分层读取代价出发，组合准入、访问位、幽灵记录与命中提升。图 15 将准入和第二次机会分别消融；表 3、图 14 把总命中、分层命中和实际 prefill 分开，支撑“缓存命中位置影响收益”的核心论点。仍需注意：这些组件交互并未由完整组合实验逐一分解，性能改善不能完全归因于某一组件。[^paper]

### 假设压力测试

公共系统提示很长、深层前缀反复出现、共享模式随时间突变，或租户使用长度差异很大时，深度与价值的相关性可能变化。累计均值阈值可能把早期阶段带入当前决策；幽灵队列有限时，间隔很久的复用可能被视为新前缀。这些是根据机制提出的压力场景，不是论文已证明的失败案例。[^paper]

缓存准入拒绝不会自动让推理出错：正确实现应重算未命中部分。实际部署还要验证异步写回完成前请求重访、重复请求并发、块移动期间的引用与释放、模型版本及租户隔离；论文没有充分覆盖这些并发正确性问题，不能仅凭单请求轨迹回放证明。[^paper]

### 实验可信度与系统性缺陷

模拟覆盖四条真实来源轨迹、两种模型足迹和多种基线；实际 vLLM 测试主要使用两条 Qwen 轨迹。顺序回放可隔离替换策略，却不保留真实到达时序，也不能量化高负载下搬运争用和排队。论文的两卡 TP/DP 实验支持基本可用性，不代表跨节点缓存共享、弹性扩缩容或大规模控制面已验证。[^paper]

三层实验统一使用 SSD FIFO，有利于隔离上层策略，但结果不说明这种 SSD 策略对所有设备、寿命和写入负载都是最优。论文给出平均记账时间，未系统报告不同租户的元数据占用、SSD 写放大、故障恢复与能耗。[^paper]

## 局限与后续工作

- 在同一 vLLM／SGLang 版本、固定 HBM 与主机预算下，比较 Buoy、LRU 和 HiCache 的写入／淘汰策略，分层记录命中、回载字节、重算和 TTFT 分位数。[[SGLang-HiCache]] 描述系统集成，不能直接把它与一个独立替换策略当成同类基线。
- 回放真实到达时间并加入突发并发、主机竞争和慢 SSD，测试准入异步写入、排队及 PCIe 争用；同时报告输入 token 吞吐与请求吞吐。
- 对比累计平均、近期窗口与其他深度阈值估计，构造长公共前缀、新热点和周期性复用轨迹，统计被拒绝后重算的成本。
- 统计幽灵队列的实际字节数、块 ID 计算和同步开销；在 SSD 模式下单独报告其真实 KV 写入量、寿命与多层淘汰行为。
