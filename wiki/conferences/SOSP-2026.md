## 五条研究主线

### 1. 推理服务：把不同约束变成调度决策

[[Janus-SOSP26]] 面向生产多模型负载，在常驻池与弹性池之间分配副本、按模型与请求特征路由；[[ACDC-SOSP26]] 面向离线批处理，在真实生产日志中区分长短请求、并行策略与尾部空转；[[LLM-42-SOSP26]] 则处理另一个约束：同一提示的可复现输出，允许普通动态批处理先跑，再验证有确定性需求的请求。三篇的目标不能用单个吞吐倍数排序：Janus 关心多模型 SLO 与容量，ACDC 关心离线完成效率，LLM-42 还需核对确定性与回滚开销。

摘要级证据的 [[SANDHI-SOSP26]] 聚焦多模型显存权重共享，[[StreamInfer-SOSP26]] 聚焦 MoE 专家并行跨 GPU 屏障，[[Bedrock-WLM-SOSP26]] 聚焦跨区域生产负载管理，[[LMTracer-SOSP26]] 聚焦 LLM 在线性能定位。四者覆盖不同层，值得后续拿全文比较“模型驻留、单请求调度、跨区域路由、观测反馈”的闭环。当前不能据摘要推导它们各自的图表或适用边界。

### 2. 训练与工作流：状态跨阶段移动

[[TensorHub-SOSP26]] 管 RL 训练中的权重传输及弹性副本，让更新中的权重安全、及时到达 rollout 端；[[CrystalLLM-SOSP26]] 用少量 GPU 构造目标规模的训练执行图，让所关心的 rank 真跑、其他 rank 回放，适合调试性能。两者分别处理真实运行和仿真诊断，不能把“权重分发速度”和“仿真精度”视为同一指标。

### 3. GPU 层：谁在决定计算边界

[[MeldKernel-SOSP26]] 让变长 attention 的计算在 SM cluster 内外动态映射并即时归约，以减少跨 SM 长尾和全局中间态。

摘要级证据的 [[EnerTune-SOSP26]] 从能耗与 SLO 共同出发做 GPU 任务放置。它提醒人们高利用率并不等于低能耗；未来比较 GPU 多任务方案时，除了前台延迟和后台吞吐，还应在同一任务组合上记录功率、焦耳/请求和搬迁开销。

### 4. 模型状态：同一份权重应在何处、以什么形式存在

[[TensorDex-SOSP26]] 在模型仓库里按 tensor 粒度选择差分参考，优化长期存储占用与读取吞吐；[[TensorHub-SOSP26]] 在 RL 训练期间转移动态权重；[[SANDHI-SOSP26]] 据摘要在在线多模型服务时合并权重组件以节省 HBM；[[Anchor-SOSP26]] 据摘要把 GPU 显存对象与 worker 进程寿命解耦。这四篇可画成同一份权重的生命周期：**仓库保存 → 训练分发 → 在线驻留 → 进程故障后恢复**。每段对“相同”的定义不同：TensorDex 要位级无损；SANDHI 可能接受满足准确率阈值的合并；Anchor 关注故障后内存对象是否仍可安全使用。因此跨段共享不能只看容量数字。

### 5. 上下文与可观测性：分别看语义状态、运行成本

[[llmovoice-SOSP26]] 管理语音应用的语义、伴随语音和环境状态，通过多保真记忆构造有界提示，而非管理 GPU KV cache。[[LMTracer-SOSP26]] 的公开摘要指向生产 LLM 系统的细粒度 GPU 性能诊断，但还没有全文可核对。

## 下一轮应核验的问题

1. **证据等级升级**：拿到 6 篇缺失 PDF 后，逐篇核对系统名、方法细节、模型/硬件、P99 与消融；当前摘要数字一律不可当成完整版结论。
2. **统一服务指标**：对 [[Janus-SOSP26]]、[[LLM-42-SOSP26]] 和 [[EnerTune-SOSP26]]，在相同请求长度分布、SLO、GPU 成本和功率口径下比较达标率/美元/焦耳。
3. **权重生命周期故障注入**：把 [[TensorDex-SOSP26]] 的冷启动、[[TensorHub-SOSP26]] 的更新、[[Anchor-SOSP26]] 的进程恢复连接起来测，特别检查版本一致性和跨租户隔离。
4. **可观测性**：核对 [[LMTracer-SOSP26]] 在单推理栈中定位问题的采样偏差、探针开销和因果归因边界。
